# Hosting and database for Build-a-bot: decision memo

*2026-10-14. Answers Diego's questions: "Is Vercel the right software to use for this? Or AWS or Google or something else?" and "Is Supabase, Google, AWS or Cloudflare the best database? Look into Cloudflare especially."*

## Bottom line

Stay on **Vercel + Supabase Postgres**. Both run the app as it is, and you already pay for Supabase Pro. Move the Vercel team to **Pro ($20/month) before taking any payment**: Hobby is for non-commercial use only, and it rejects the per-minute cron in `vercel.json`. Add the Cloudflare pieces that are free and fit now: Turnstile, then Email Routing for bot inboxes and Workers AI Whisper as the transcription fallback. Don't move hosting to Cloudflare Workers, which would take about a week of refactoring to save $15–30 a month. Don't move the database to D1, which would mean rewriting the data layer.

## What the host must handle

SSE chat turns that run for minutes; 12 routes, every channel webhook among them, that finish their work in `after()`; a tick every minute; 25-second Bridge long-polls; ~80 KB audio chunks; a Postgres pool kept in `globalThis`.

## 2. Database

The code needs real Postgres: 28 tables (26 `jsonb` columns), a PL/pgSQL append-only trigger, RLS on 30 tables, 49 raw `sql` fragments, a `FOR UPDATE` CTE, and 3 interactive transactions (two use `SET LOCAL`). Any managed Postgres runs it unchanged.

| Option | Fits? | Cost at this scale | Notes |
|---|---|---|---|
| **Supabase** (Pro already) | Yes | About $10/month more for a new Micro project (1 GB) | Shared pooler is IPv4 (Vercel is IPv4-only). 7 days of daily backups; PITR $100/month. Use us-east-1, next to Vercel's iad1. |
| **Neon** (Databricks agreed to buy it in May 2025) | Yes | $0.106/CU-hour, $0.35/GB-month, no minimum. The per-minute tick blocks scale-to-zero: about $19 at 0.25 CU | Built-in pooler, 7-day restore, good preview branches. |
| **Cloudflare D1** | **No** (SQLite) | About $0 on Workers Paid | No Postgres jsonb operators, timestamptz, RLS, PL/pgSQL or `FOR UPDATE`. Multi-statement atomicity only through `batch()`. 10 GB cap. |
| **Hyperdrive** | Pooler only | Free (100k queries/day) | Useful only if the app runs on Workers. |
| **Cloudflare-native Postgres** | None exists | n/a | Since 2026-06-18, PlanetScale databases can be created and billed through Cloudflare. |
| **PlanetScale Postgres** | Yes | $5 single node; about $15 for HA (third-party figure) | Pairs with Hyperdrive. |
| **Prisma Postgres** | Probably | Free up to 200k operations; $10 for 1M, then $8 per million | The per-minute tick alone can eat most of the free tier. |
| **Railway Postgres** | Yes | About $2–5 | Not highly available. Backups reportedly need Pro. |
| **RDS t4g.micro / Aurora Serverless v2** | Yes | About $12 / at least $44 (the tick keeps it awake) | VPC setup; RDS Proxy for serverless. |
| **Aurora DSQL** | **No** | n/a | No triggers or PL/pgSQL, apparently no RLS policies, at most 3,000 rows per transaction. |
| **Cloud SQL / AlloyDB** | Yes | About $8–11 (no SLA) / about $227 or more | |

**Moving to D1 means** rewriting the schema for SQLite, replacing the jsonb and time SQL, rebuilding the receipts guard, turning transactions into batches, and re-checking 113 files plus the PGlite-based tests: 1–2 weeks and migration risk, to save about $10 a month.

## 3. Cloudflare, product by product

| Product | Use here | Verdict |
|---|---|---|
| **Turnstile** | Bot creation, which also creates anonymous accounts | **Now.** Free, unlimited, and works on Vercel. About 40 lines of code. Vercel BotID Basic is a free alternative. |
| **Email Routing + Email Worker** | One inbound address per bot | **Soon.** Yes, this works: buy the brand-free bot domain at Cloudflare and turn on a catch-all (apex only). A ~50-line Worker posts each message to a new `/api/webhooks/email/cloudflare` route; the router already matches by handle. Inbound is free and unlimited, while AgentMail charges per inbox ($200/month for 150). Keep Resend for sending. |
| **Workers AI Whisper** (`whisper-large-v3-turbo`) | Meeting transcription | **Soon, as the fallback.** About $0.03/audio hour vs Groq's $0.04, plus ~3.5 free hours a day. Not OpenAI-compatible (base64 JSON), so it needs a small adapter; test on webm/opus chunks. |
| **AI Gateway** | Logs, caching and per-user spend limits for the included models | **Later.** Free core. Nebius can be added as a custom provider. |
| **Durable Objects / Agents SDK** | Per-bot state, exact-time alarms, cheap always-open Bridge connections | **Later, maybe.** A strong fit, but it moves the agent loop out of Postgres. |
| **Registrar / DNS** | At-cost renewal of build-a-bot.site | **After ~2026-12-12** (ICANN's 60-day lock after registration). Requires Cloudflare DNS; records can still point at Vercel. Confirm the `.site` price. |
| **R2** | File storage | **Skip.** Audio is never stored. |

## 4. Recommendation

**(a) Walkthrough tonight: Vercel + Supabase, no code changes.**
- On Hobby, the per-minute cron fails the deploy. Either upgrade to Pro ($20), or set the cron to daily and have Supabase `pg_cron` + `pg_net` call `/api/cron/tick` every minute with `CRON_SECRET`.
- Use Supabase's session-pooler URL (port 5432) so first-start migrations keep their advisory lock.
- A walkthrough that earns nothing is within Hobby's terms.

**(b) Launch, before Stripe goes live: Vercel Pro + Supabase (new project, us-east-1) + Turnstile.**
- **Cost:** about **$30–45 a month** new: Vercel $20–35, Supabase ~$10 more (org ~$35 → ~$45), Cloudflare $0. LLM, Twilio, Tavily and transcription usage come on top.
- **Required code changes:** none.
- **Worth adding:** Turnstile on bot creation; `maxDuration = 800` for meeting notes (the 4-hour-meeting issue in DECISIONS); a 4 MB audio-chunk cap (Vercel's limit is 4.5 MB); `AUTO_MIGRATE=0` with migrations from CI and the transaction pooler (port 6543) at runtime.
- **Within weeks:** Email Routing for bot inboxes; the Workers AI transcription fallback.

**Revisit if** Vercel passes ~$100 a month or long-polls dominate the bill: slow the polling, or move to Railway or Render with `next start` (no code changes, no duration caps).
